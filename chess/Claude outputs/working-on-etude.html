Working on Étude

For Claude, at the start of a chat about the chess app. How the code works is in the code: start with the comment at the top of index.html, then the one at the top of its main script, sw.js and server/worker.js. This page is only what the code can't say.

Where it is

  • David's GitHub Pages repo butterflyresonance.github.io, folder chess; on his PC Documents\butterflyresonance.github.io\chess (OneDrive). He pushes himself, with commit.bat, which uses VERSION as the commit message.
  • The server is his Cloudflare Worker etude-tables.subjectification.workers.dev. Cloudflare builds it from the repo on every push (npx wrangler deploy --config chess/server/wrangler.toml). It needs no secrets.
  • Claude outputs holds backups and tools; it isn't published.

How he wants changes made

  • When he asks a question, answer it; don't start work. When he says to check first, propose and wait.
  • Before changing index.html, copy it to Claude outputs/index-backup-DATE-before-WHAT.html. Bump VERSION (YYYY-MM-DD.N-word, letters, digits, dots and hyphens) with every change.
  • Test in a real browser (Playwright) at phone size and laptop size, and look at the screenshots, not only the behaviour. His friends use iPhones (Safari); he uses Android Chrome and Firefox on Windows.
  • Online features: run the server locally with wrangler dev and point the app at it with localStorage['table:server'] = '"ws://127.0.0.1:8787"'. The cloud workspace can't reach Cloudflare.
  • After saving to his folder, check the md5 on his PC matches. Give each file a unique name when staging it, or an old copy can be written.
  • Keep each function's comment and each file's header up to date in the same edit. Comments describe the code as it is, never how it used to be (except in Migrations, which is for that).
  • One-off clean-ups of older saved data go in the Migrations section near the end of the script.
  • Guides and documents for him: HTML files, not Markdown.

Words on screen

  • Plain, specific and direct; no flair, no dramatic phrasing.
  • Never name something by how it used to be ("Reconnecting", not "Reconnecting by itself").
  • The same feature has the same name everywhere ("Best move", never sometimes "Hints").
  • Avoid British phrases that read oddly to his friends ("Resume a game", not "Carry on").
  • Controls for one mode appear only in that mode; shared settings are the same everywhere.

Decided: don't reopen without a reason

  • No analytics.
  • Openings are not marked sound or unsound: he wants to find out by playing them.
  • The tactics coach lists everything, with whether it works, rather than choosing for him.
  • "Engine plays" stays available in online games.
  • Several piece sets are CC BY-NC-SA: this matters if donations are ever added.
  • Famous games come from PGN Mentor files and are checked for legality; descriptions are in our own words; Tal stays represented; no collections by player.

Ideas he has raised, not built

  • Opening guidance: suggested moves with reasons, reply trees and traps, starting with the London.
  • Lichess Masters search from a position; "guess the next move" in famous games.
  • Cosmetic unlocks as rewards (piece sets, boards); a donation option.
