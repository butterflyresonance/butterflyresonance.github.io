Moving Étude to its own domain

From butterflyresonance.github.io/chess to a domain of its own, for example etudechess.com, served by Cloudflare. About an hour of your time, spread over a few sittings, and roughly US$11 a year for the domain.

What it will look like

  • One Cloudflare Worker serves everything. The same Worker that runs the server now (etude-tables) also serves the app's files, on etudechess.com. Cloudflare now recommends Workers with static files for new sites; Pages still works, but it would be a second project to look after.
  • It stays the same Worker. Accounts, friends, online games and chat are stored in that Worker's Durable Objects, so they come across untouched. Only where the code comes from changes.
  • Its own GitHub repo, etude, separate from your website. The app goes in site/, the server in server/, and Cloudflare rebuilds on every push, as now.
  • The app talks to the server at its own address (etudechess.com/u/…), so there is no second address to configure.

What comes across and what doesn't

Comes acrossDoesn't
Your account (name, code, key), through the redirect link
Friends, online games, chat (they're on the server)
Look and sound settings, and your puzzle rating, through the redirect link		 Game history on the device
Games against the computer or on one device that are under way
Saved set-up positions
Notifications (turn them on again on the new site)
The home-screen icon (add the new site, remove the old one)

Browsers keep each website's data separately, which is why anything kept only on the device stays behind. The redirect page reads what it can on the old address and hands it to the new one in the link it opens.

The steps

1 · Buy the domain you

  1. In the Cloudflare dashboard, open Domain Registration → Register Domains. Your email address on the Cloudflare account must be verified first.
  2. Search for the name, for example etudechess.com, and press Purchase on the one you want.
  3. Choose 1 year (auto-renew is on; leave it on). Enter your contact details and a card, accept the agreements, and press Complete purchase.
  4. Tell me the domain you bought.

Cloudflare charges registry cost for domains; a .com is about US$10.50 a year. Its whois privacy is included.

2 · Make the new repo you

  1. On github.com: New repository, name etude. Private or public both work; Cloudflare can build from either. Don't add a README. Press Create repository.
  2. Make it a folder on your PC: in a terminal in Documents, run git clone https://github.com/butterflyresonance/etude.git.
  3. In the Claude desktop app, connect that folder (Documents\etude) to this chat.

3 · Fill the repo me

  • site/: the app as it is now, with the server address set to its own domain.
  • server/worker.js: the server, with the new domain added to the sites allowed to use it.
  • wrangler.toml and package.json at the top of the repo, telling Cloudflare to serve site/ and run server/worker.js for everything else. The Worker's name, its Durable Objects and its migrations stay exactly as they are.
  • A commit.bat for the new folder, the same as yours.

Then you push it with commit.bat. Nothing changes for anyone yet: Cloudflare is still building from the old repo.

4 · Point the Worker at the new repo you

  1. Cloudflare dashboard: Workers & Pages → etude-tables → Settings → Build.
  2. Under Git repository, disconnect butterflyresonance.github.io, then connect etude (branch main).
  3. Set Root directory to empty (the top of the repo), Build command to empty, and Deploy command to npx wrangler deploy. Save.
  4. Start a build (Deployments → Retry, or push any change). When it succeeds, open https://etude-tables.subjectification.workers.dev: it should now show Étude itself, not “Nothing to see here”.

If the build fails, open it, copy the last 20 or so lines of its log, and paste them to me.

5 · Put the Worker on the domain you

  1. Workers & Pages → etude-tables → Settings → Domains & Routes → Add → Custom domain.
  2. Enter etudechess.com and confirm. Cloudflare adds the DNS record and certificate by itself; it can take a few minutes to start working.
  3. Do the same again for www.etudechess.com.
  4. Open https://etudechess.com. Try it with a test account (for example David-Test): make a game, play a few moves, then delete the test account. Don't make your real account here: it comes across in step 7.

6 · Turn the old address into a redirect me, then you

I replace chess/index.html in your website repo with a small page that, when opened:

  • reads your account key, settings and puzzle rating from the old address;
  • turns off notifications for the old address, so you don't get each one twice;
  • opens https://etudechess.com with those in the link, after the # (that part of a link never leaves the browser, so it isn't sent to any server);
  • passes a game link (#r=…) through, so an old link to a game opens that game.

The new site takes them in, saves them, and removes them from the address bar. Then you push the website repo with commit.bat.

7 · Move each device you, and each friend

  1. Open the old address (or the old home-screen icon) once. It lands on etudechess.com, already signed in to your account.
  2. Your account → Notifications: turn them on again.
  3. Add etudechess.com to the home screen and delete the old icon. On iPhone this is needed for notifications.

Friends do the same: they only need to open the old link once. Anyone who never opens it keeps their account on the server and can bring it across later with their key (Your account → Show key → Copy link, opened on the new site).

8 · Make yourself admin you, then me

  1. On the new site: Settings in any game → Copy report, and paste it to me. The account line has your account id (your public key; it can't be used to sign in).
  2. I add it to ADMIN_IDS in wrangler.toml, and you push. Your account screen then has Admin → Accounts.

Later

  • Donations: a Ko-fi, Buy Me a Coffee or GitHub Sponsors link on the site. Before taking money, drop the piece sets licensed CC BY-NC-SA (non-commercial), or get permission from their artists.
  • A privacy page: what the server keeps (a name, friends, games, chat, notification addresses), where (Cloudflare), and how to delete it (Delete account).
  • Credits: Stockfish is GPL: keep a credits page that links to its source, and to the app's own repo if it's public.
  • Google Play, if wanted: the web app can be packaged as an Android app (a Trusted Web Activity). Google charges US$25 once, and a new personal developer account has to run a closed test with 12 testers for 14 days before it can publish.

Going back

Every step can be undone: point the Worker back at butterflyresonance.github.io in step 4's screen, and restore chess/index.html from its backup in Claude outputs. The server's data isn't touched by any of it.
